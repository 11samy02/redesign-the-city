# Egkomi City Expansion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grow Egkomi City to a 7x7 mat, 8 rounds, 4 buys per turn, a stacked construction site, a 22-kind tile set with household roles (Student, Worker, Child, Older), a harsher loan, and a 24-card hidden-circumstance deck, then polish the UI and stop for the owner's approval.

**Architecture:** Rules stay in `scripts/core/` (pure `RefCounted` scripts, tested headless). A new `roles.gd` holds role/need/like data; `tile_defs.gd` gets the new kinds and household variants; `scoring.gd` evaluates happiness **per citizen** and returns the same result shape as today plus a `members` list per home; `circumstance_defs.gd` owns every card's rule so it can be unit tested with a plain context dictionary. The shop becomes a list of stacks (`{tile, count, start}`) instead of 36 slots. UI is rebuilt around those two changes at the existing 1600x900 virtual viewport (`canvas_items` stretch).

**Tech Stack:** Godot 4.7 / GDScript, SVG art generated by Python (`tools/gen_art.py`, `tools/gen_circumstances.py`).

**Spec:** `docs/superpowers/specs/2026-10-31-egkomi-city-expansion-design.md`

## Review Focus

- A player with fewer than 4 players (2 or 3): the shop must still hold enough tiles for 4 buys x 8 rounds each, and stacks removed by the fewer-players rule must not leave empty headings.
- A mat with no homes, or only homes with no roads: evaluation must not crash and must not divide by zero (average happiness, served counts).
- A home whose roles need a service kind that does not exist in a small shop (for example the 3-player shop has no University left): the game must still be winnable and the complaint text must still read sensibly.
- A player who cannot afford anything at all and has no loan available (all remaining stacks cost more than money + 0 loans): the turn must still be endable or a loan offered; no soft-lock.
- A bot turn on a near-full 7x7 mat must finish in a few seconds (candidate evaluation is much larger than on 4x4).
- Window sizes: the shop (about 32 stacks) must not overflow at 1600x900, and must not overlap the mat at a maximised 1920x1080.

Each `apartments[]` entry (it holds every home, student residences included) keeps `index, kind, citizens, routes, green_sources, green_bonus, pollution, sp` and gains `"members": Array` of `{"role": String, "needs": Array of {"id": String, "name": String, "met": bool, "source": int}, "like": bool, "like_source": int, "dislike": bool, "heat": int, "effects": Dictionary, "raw": int, "happiness": int, "complaint": String, "complaint_detail": String, "improve": String}`. Home-level `happiness` is the rounded average of its members (used for the home badge colour), `sp` the sum of member happiness, `amenity_bonus` is removed (callers use `members`).

Rules to encode per citizen (spec, "Citizen roles" and "Shared by everyone"):
`need_score` = +2 both needs met, 0 for one, -2 for none. A need is met if a tile of an accepted kind is in `routes` (for `park`: a PARK within `in_park_area`). `like` = true if any tile of the role's like kinds is in `routes`, or a road of a like street type is on any route path or 4-adjacent to the home; adds +1 once. `green` = `min(green_sources.size(), 2)`. `heat` = `role.heat_factor` if any route to a tile that satisfies one of the member's needs has `length >= LONG_ROUTE` and is not shaded, else 0. `dislike` = a tile of `dislike_kind` 4-adjacent -> -1. `raw = need_score + like_bonus + green + circumstance_delta - heat - pollution_penalty - dislike`; `happiness = clampi(raw, -3, 3)`. A member with happiness below 0 files a complaint: `"Accessibility"` with `complaint_detail = Roles.missing_text(first unmet need)` when any need is unmet; otherwise the heaviest of Walkability/Greenery/Pollution by the existing weights (`detail` = the generic meaning). `room`/`room_homes` accounting uses the same `improve` logic as today with "unmet needs count" replacing `amenity_bonus == 0`. A service tile reached by no home at all counts in `unused` (1 point each).
